# Desktop-first: проверка и экраны

## Область изменений

Переделан существующий UI, без переписывания проекта. Шаги 0–4 сохранены отдельными коммитами, после каждого выполнялись `npm test`, `npm run build` и проверка доступности dev-сервера.

`src/scoring`, `src/challenge`, `reference.json`, остальные музыкальные файлы и все тесты скоринга не изменены. В `src/audio/capture.ts` только необязательный аргумент `deviceId` и передача его в getUserMedia; остальной аудиокод не менялся.

## Проверка

- Google Chrome 154.0.8037.98, отдельный временный профиль Playwright. Полный сценарий проверен на dev-сервере и production-сборке.
- Полный путь: имя → песня → разрешение → выбор USB-входа → старт → пауза/продолжение → результат → оба A/B-режима → фрагмент → clipboard → вторая вкладка → призрак → дуэль.
- Виртуальное устройство выдаёт синтетический сигнал на −5 полутонов с тремя намеренными ошибками. Сигнал проходит настоящий AudioWorklet, pitchy и неизменённый скоринг.
- Проверены Space, Enter, R; Esc с отменой и подтверждением выхода. Часы пения не движутся на паузе. При вводе имени пробел остаётся обычным символом.
- Проверены сохранение и восстановление `deviceId`, точная передача constraint, отказ в доступе, отсутствие устройства и занятый вход. Отдельно проверены живой уровень/точка высоты, нулевой уровень при тишине и ручное копирование при отказе clipboard.
- 30 проверок viewport в полном прогоне; подробные размеры — [checks.json](docs/qa/desktop/checks.json). На 1366×768 и 1920×1080 высота страницы равна viewport. Нет горизонтального переполнения. На 800×768 разрешена обычная вертикальная прокрутка.
- Три момента результата видимы без внутренней прокрутки; подтверждение копирования и поле ссылки также помещаются в окне.
- Необработанных ошибок JavaScript/ошибок консоли в основном прогоне нет.
- 22 исходных теста проходят без изменений, включая +5/−7, задержку и вибрато. Строгая TypeScript-проверка и production build проходят.

## Что остаётся риском демо

- Автоматизация не проверяет физические микрофоны, драйверы и разрешение на запись в самой ОС. Перед показом проверь выбранную гарнитуру и рост индикатора.
- Edge является целевым браузером, но отдельный фактический прогон здесь выполнен только в Chrome. Firefox и Safari — по возможности.
- Коррекция собственного тембра через PitchShift остаётся экспериментальной; синтезированный ориентир надёжнее для демонстрации. DSP по заданию не изменялся.
- Bluetooth может давать задержку больше окна компенсации. Проводные наушники предпочтительны.
- Уход вкладки в фон прерывает запись, как и в исходной версии. На время пения не переключай вкладки.
- При масштабе браузера выше 100% возможна прокрутка. Не используется обрезание страницы для маскировки нехватки места.
- В старых шаблонах объяснений скоринга возможны неточные формулировки, например нулевая медианная ошибка внутри смешанного ошибочного отрезка; алгоритм и шаблоны `src/scoring` намеренно оставлены без изменений.
