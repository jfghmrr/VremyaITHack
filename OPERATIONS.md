# Запуск и обслуживание

Быстрый запуск описан в [START_HERE.md](START_HERE.md). Все команды ниже выполняются из корня репозитория. Перед обновлением действующей установки сохраните базу и `.env`.

## Настройки

Локально достаточно `docker compose up --build -d --wait --wait-timeout 180`. Сайт откроется на `http://localhost:8080`. Дополнительные параметры задаются в `.env` по образцу `.env.example`.

| Переменная | Назначение |
| --- | --- |
| `PEREPEV_PORT` | Порт на компьютере; по умолчанию 8080 |
| `APP_ORIGINS` | Допустимые адреса браузера, через запятую, с протоколом и портом |
| `POSTGRES_PASSWORD` | Пароль базы; для публичного сервера обязательно задать свой |
| `COOKIE_SECURE` | `false` для локального HTTP, `true` для HTTPS |
| `WORKER_TOKEN_SHA256` | SHA-256 токена GPU-обработчика, 64 шестнадцатеричных символа |
| `PERF_DEADLINE_S` | Срок точной оценки после окончания песни, по умолчанию 20 секунд |
| `PERF_LIMIT_PER_HOUR` | Число попыток точной оценки на IP за час, по умолчанию 300 |
| `PUBLIC_ORIGIN` | Адрес сайта для OAuth; иначе берётся первый адрес `APP_ORIGINS` |
| `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | Настройки приложения Яндекс ID |
| `VK_CLIENT_ID`, `VK_CLIENT_SECRET` | Настройки приложения VK ID; оба поля включают кнопку, секрет при PKCE-обмене не передаётся |
| `SITE_DOMAIN` | Домен для варианта с `compose.server.yaml` |

Токен создают командой `openssl rand -hex 32`. Сам токен нужен только обработчику, его хеш — API. Не добавляйте токен, `.env`, резервные копии и файлы OAuth-настроек в Git. Без настроенного и доступного обработчика API отказывает в приёме голоса, а сайт сохраняет локальную оценку.

`DATA_DIR=/data` задан в образе API. `TRUST_PROXY=true` задан в Compose и не меняется через `.env`. Не увеличивайте срок оценки до нескольких минут: резервная очистка удаляет записи после семи минут с момента создания попытки.

Изменение `POSTGRES_PASSWORD` в `.env` не меняет пароль уже созданной базы. Для этого нужна отдельная смена пароля внутри PostgreSQL с согласованным обновлением настроек, а не удаление тома.

## Обновление и диагностика

```sh
git pull --ff-only
docker compose up --build -d --wait --wait-timeout 180
docker compose ps
docker compose logs --tail=100 api
docker compose logs --tail=100 web
```

Сохраняйте прежнее имя Compose-проекта: от него зависят имена томов. Если установка ещё не является Git-копией, сначала подготовьте чистый каталог репозитория и перенесите настройки; не распаковывайте файлы поверх работающего дерева без сравнения. Запуск с тем же именем проекта подключит существующие тома. Миграции API применяет при старте.

`docker compose down` останавливает установку; `docker compose up -d` запускает снова. **`down -v` удаляет данные** и не подходит для обычного перезапуска.

Независимую тестовую копию запускают с отдельным именем и портом:

```sh
PEREPEV_PORT=8087 APP_ORIGINS=http://localhost:8087,http://127.0.0.1:8087 \
  docker compose -p perepev-test up --build -d --wait --wait-timeout 180
```

## Резервная копия

PostgreSQL хранит аккаунты, историю, друзей и результаты. Valkey содержит временное состояние матчей. Том `data` содержит записи на срок до 10 минут и свои треки на 24 часа; его не включают в долгосрочную резервную копию.

Для стандартного проекта `perepev` на macOS/Linux или в Bash:

```sh
bash deploy/backup.sh
```

Получится `backups/perepev-ДАТА-ВРЕМЯ.dump`. Для PowerShell можно обойтись без двоичного перенаправления:

```powershell
docker compose exec -T postgres pg_dump --format=custom --no-owner -U perepev -d perepev -f /tmp/perepev-backup.dump
docker compose cp postgres:/tmp/perepev-backup.dump ./perepev-backup.dump
```

На **целевой** установке восстановление перезаписывает базу. Сначала запустите PostgreSQL, затем остановите сайт и API:

```sh
docker compose stop web api
docker compose cp ./perepev-backup.dump postgres:/tmp/perepev-restore.dump
docker compose exec -T postgres pg_restore --clean --if-exists --no-owner -U perepev -d perepev /tmp/perepev-restore.dump
docker compose start api web
```

Гостевая история из браузера в копию базы не входит. Текущие матчи перед переносом следует завершить. Копии базы содержат персональные данные: храните их с ограниченным доступом и собственным сроком удаления.

## Сервер за nginx

Для `https://perepev.lumnex.ru` подготовлена схема с системным nginx и контейнерами на `127.0.0.1:8097`. Здесь используется **обычный `compose.yaml`**, без `compose.server.yaml`.

```sh
git clone https://github.com/jfghmrr/VremyaITHack.git perepev
cd perepev
cp deploy/server-nginx.env.example .env
chmod 600 .env
```

Укажите в `.env` пароль базы, адрес сайта, хеш токена обработчика и при необходимости OAuth-настройки. Пароль не оставляйте пустым: иначе Compose подставит локальное значение. Для значения, включённого в URL базы, удобно использовать случайную шестнадцатеричную строку.

```sh
docker compose -p perepev up --build -d --wait --wait-timeout 180
curl -fsS http://127.0.0.1:8097/api/health
sudo bash deploy/nginx/install-site.sh
```

Установщик требует root, проверяет `nginx -t`, конфликт домена, сертификат и доступность проверки домена. При ошибке возвращает прежние файлы сайта. Другие сайты не меняет. Повторный запуск нужен при изменении шаблона nginx; ручные правки установленного файла перед этим сохраните отдельно.

Установщик поддерживает DNS-01 через Cloudflare и HTTP-01 через webroot. Выбор задаётся после `sudo`, например:

```sh
sudo ACME_METHOD=dns-cloudflare CF_CREDENTIALS=/path/to/cloudflare.ini bash deploy/nginx/install-site.sh
```

По записи предыдущего развёртывания внешний порт 80 этого сервера попадал на другое устройство, поэтому применялся DNS-01. Не переносите это предположение на другой сервер: проверьте маршрутизацию и DNS. Сертификат обновляет `certbot.timer`, после обновления выполняется reload nginx.

Проверки после установки:

```sh
curl -fsS https://perepev.lumnex.ru/api/health
sudo nginx -t
sudo certbot certificates --cert-name perepev
sudo systemctl status certbot.timer
```

В браузере проверьте вход, каталог и подключение к дуэлям по `/api/ws`. `worker: false` означает отсутствие GPU-обработчика, а не поломку локального пения. Публикация коммита в GitHub сама по себе не обновляет сервер. Автоматические проверки GitHub Actions отключены; команды для локального запуска сохранены в репозитории.

### Адрес клиента и журналы

nginx заменяет `X-Forwarded-For` адресом соединения, Caddy передаёт API один проверенный адрес. Это нужно, чтобы разные клиенты не попадали в общий лимит Docker-шлюза. Caddy доверяет частным адресам на участке за nginx; при изменении сетевой схемы эту границу нужно пересмотреть.

Шаблон отключает `access_log` для HTTP и HTTPS этого сайта. Уже установленный старый шаблон сам не обновится. Журнал ошибок nginx может содержать IP; настройка его хранения — отдельная обязанность владельца сервера. Входящий заголовок клиента не должен менять его лимит запросов.

nginx пропускает тела до 25 МБ, WebSocket с часовым тайм-аутом и запросы API без буферизации с ожиданием до 90 секунд. Сам API применяет меньшие лимиты по маршрутам. Заголовки безопасности задаёт Caddy.

## Отдельный сервер с Caddy

Этот вариант подходит, если порты 80 и 443 свободны. Нужен Docker Compose 2.24.4 или новее: серверный файл использует `!override`.

```sh
cp deploy/server.env.example .env
# Заполнить домен, пароль базы и дополнительные настройки.
docker compose -f compose.yaml -f compose.server.yaml up --build -d --wait --wait-timeout 180
```

Caddy получает сертификат сам. Домен и входящие порты должны быть доступны извне. В этом режиме Caddy не доверяет присланному `X-Forwarded-For`, а считает адресом клиента адрес соединения. Два человека для совместной игры должны открыть один сервер: отдельные localhost-установки не связаны.

## GPU-обработчик

Установка Windows / NVIDIA: [инструкция](deploy/gpu-worker/README.md), скрипт `deploy/gpu-worker/setup.ps1`. Обработчик получает задания исходящими HTTPS-запросами. Входящие порты на его компьютере не нужны.

Для смены сервера измените `server` в `C:\Perepev\worker.json` и перезапустите задачу `PerepevWorker` из PowerShell администратора. Хеш установленного токена должен совпасть с серверным `WORKER_TOKEN_SHA256`. После подключения `/api/health` покажет `worker: true`.

```powershell
Stop-ScheduledTask PerepevWorker
Start-ScheduledTask PerepevWorker
```

Модели занимают заметную часть памяти видеокарты. На использованной RTX 3070 Ti 8 ГБ по прежним замерам оставался небольшой запас, поэтому параллельные GPU-задачи перед показом лучше остановить. При первом запуске модели скачиваются; при полном кеше повторный старт может работать без доступа к Hugging Face. Не задавайте `HF_HUB_OFFLINE=1` до первого скачивания.

Для разработки без NVIDIA, из `gpu-worker`:

```sh
uv sync --frozen --extra cpu
uv run --frozen --extra cpu pytest -m "not models"
```

CPU-режим не является равноценной заменой GPU при стандартном сроке 20 секунд: прежний замер обработки составлял около 25 секунд. Модельные тесты запускаются отдельно и требуют загрузки весов. На Mac используется CPU; MPS отключён после проблемы с расходом памяти.

## Разработка и повторная подготовка музыки

Docker-запуск не требует Node.js, Rust и Python на хосте. Для разработки версии берутся из файлов фиксации зависимостей. Сборка автоматически проверяет ядро оценки и фронтенд; полный набор проверок описан в [отчёте](docs/release-check.md).

Playwright регистрирует аккаунты и создаёт матчи. Запускайте его только на отдельной тестовой базе. Для Chromium и WebKit нужны соответствующие браузеры Playwright.

Готовые музыкальные материалы уже в `web/static/songs`. Повторная подготовка описана в [каталоге](docs/vocal-catalog.md); исходные записи и рабочие кеши моделей не нужны для обычного запуска. Условия использования указаны в [LICENSES.md](LICENSES.md) и `CREDITS.json` каждой песни.

## Обновление до версии с режимом «Вместе»

Обновляйте API и сайт из одного коммита. При запуске API автоматически применяет `0007_match_mode.sql`: добавляет режим матча и согласие на передачу голоса партнёру. Текущие матчи перед обновлением нужно завершить, базу и прежние образы — сохранить.

Старый бинарник API не знает миграцию 7 и может отказаться запускаться с ошибкой `VersionMissing(7)`. Для отката используйте согласованный комплект старых образов и резервной копии базы. Простая замена только образа API не является проверенным откатом.

Редакция согласия на запись обновлена до `2026-10-18`, поэтому браузер может запросить её повторно. Совместные записи хранятся внутри закрытого тома `data`, в каталоге `coop`; они не должны раздаваться прокси как публичная статика. Отдельная очистка удаляет их после шести минут хранения и при отзыве согласия.
