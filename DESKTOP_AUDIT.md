# Шаг 0 — аудит desktop-first

- CSS уже имеет desktop-сетки; проблема — высота всей композиции, а не только направление media queries.
- Главная: hero 458–490 px, затем карточки и пояснения. Не помещается в 768 px.
- Проверка микрофона: узкая вертикальная панель 610 px.
- Результат: балл и оси в строке, остальные блоки расположены последовательной длинной колонкой.
- Дуэль добавляется внизу результата.
- Media queries: min-width 1450, max-width 1000/700/380 и prefers-reduced-motion.
- Кнопки 44 px, play 58 px, панели с отступами 30–32 px.
- Web Share API в src/ui/Duel.tsx.
- Нет bottom nav, bottom sheet, свайпов, pull-to-refresh, touchstart/touchend.
- Нет блокировки зума и мобильных 100vh-хаков. Стандартный viewport.
- Телефоны упоминаются в README/ASSUMPTIONS, но не в пользовательских экранных подсказках.
- Сохраняются Canvas, оформление, формат эталона, DSP, скоринг, кодек вызовов и тесты скоринга.
- Исключение шага 4: необязательный deviceId в Capture.open, передаваемый в getUserMedia; алгоритмы захвата не меняются.

Приёмка: главная/микрофон/пение/результат/дуэль помещаются в viewport 1366×768 и 1920×1080 при 100% масштабе. На 800 px допускается вертикальная прокрутка. Пробел приостанавливает общий AudioContext: минусовка и захват сохраняют одну временную шкалу. Выбор микрофона хранится локально, аудио — по-прежнему только в памяти.
