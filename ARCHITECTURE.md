# Архитектура Перепева

Перепев — браузерное караоке с оценкой мелодии, личной историей и дуэлями. Сервер построен как модульный монолит: один API обслуживает аккаунты, матчи и задания обработки звука. Причины выбора стека и его ограничения описаны в [технических решениях](docs/technology-decisions.md).

## Состав приложения

```text
Браузер: SvelteKit / Svelte
  микрофон → AudioWorklet → Worker / pitchy → кривая высоты
                                      └→ scoring-core WASM → локальный результат
  HTTP и WebSocket /api
            │
          Caddy → статика, музыка, шрифты
            └→ Rust API (Axum / Tokio)
                 ├→ scoring-core native → итог дуэли / точная оценка
                 ├→ PostgreSQL → аккаунты, история, матчи, очередь GPU-заданий
                 ├→ Valkey → подбор, присутствие, события, лимиты
                 └→ закрытый том data → временные записи и свои треки

GPU-обработчик (Python, Windows / NVIDIA)
  исходящий HTTPS → /api/worker/* → получение задания → обработка → результат
```

Локально наружу открыт только `127.0.0.1:8080`. На сервере проекта перед Caddy стоит системный nginx: `HTTPS :443 → 127.0.0.1:8097 → Caddy → API`. Для отдельного сервера со свободными портами 80/443 есть вариант с TLS в самом Caddy. Настройки двух вариантов нельзя смешивать; порядок запуска — в [OPERATIONS.md](OPERATIONS.md).

| Часть | Технологии | Исходники |
| --- | --- | --- |
| Интерфейс | SvelteKit 3, Svelte 5, TypeScript, Vite; статическая сборка | `web/src` |
| Звук в браузере | Web Audio, AudioWorklet, Worker, pitchy, Tone.js | `web/src/lib/audio` |
| Общее ядро оценки | Rust; wasm-bindgen для браузера | `crates/scoring-core`, `crates/scoring-wasm` |
| API | Rust, Axum, Tokio | `crates/api/src` |
| Постоянные данные | PostgreSQL 18, SQLx | `crates/api/migrations` |
| Временное состояние | Valkey 9 | `queue.rs`, `realtime.rs`, `lease.rs` |
| Раздача сайта | Caddy 2, при необходимости nginx перед ним | `deploy` |
| Обработка записей | Python 3.12, PyTorch, torchcrepe, Whisper, Demucs | `gpu-worker` |
| Контракты | JSON Schema → TypeScript | `contracts`, `web/src/lib/api/types.ts` |

Версии закреплены в `Cargo.lock`, `rust-toolchain.toml`, `web/package-lock.json` и `gpu-worker/uv.lock`.

## От микрофона до результата

AudioWorklet получает звук, а отдельный Worker выделяет высоту тона. WASM сравнивает полученную кривую с эталоном и сразу показывает результат. Основной поток браузера занят интерфейсом, а не анализом каждого звукового блока.

Базовая оценка состоит из четырёх частей: мелодические интервалы — 45%, ритм — 25%, устойчивость — 15%, покрытие — 15%. Ядро учитывает перенос тональности и ищет общую задержку в пределах ±300 мс. Низкое покрытие и постоянная нота ограничивают итог 30 баллами. Формулы находятся в `crates/scoring-core/src/score.rs` и `config.rs`.

Один исходный код ядра используется в браузере и на сервере. Это обеспечивает одинаковые правила для одинаковых входных данных. Само по себе наличие WASM не делает браузерную запись достоверной и не гарантирует одинаковый результат при разных способах извлечения высоты.

### Точная оценка одиночной попытки

Она включается только с отдельным согласием на отправку голоса. Версия согласия хранится в `localStorage`; при её изменении приложение спрашивает снова. Без согласия остаётся локальный анализ.

1. На обратном отсчёте браузер создаёт попытку через `POST /api/perf`. Если обработчик не настроен или не подавал сигнал более 30 секунд, API отвечает 503 до приёма звука.
2. Во время пения браузер преобразует звук в моно PCM16, 16 кГц, и отправляет кусками по 5 секунд. Это изменение частоты дискретизации, а не сжатие аудио. Пределы API: 400 КБ на кусок и 70 секунд на запись.
3. После `/finish` PostgreSQL получает задание. Обработчик извлекает высоту через torchcrepe, распознаёт слова Whisper и оценивает сходство записи с дорожкой подсказки через GCC-PHAT.
4. API считает итог функцией `score_precise`. Браузер опрашивает результат каждые 700 мс. Серверный срок ожидания по умолчанию — 20 секунд после окончания песни, клиентский — 25 секунд.
5. При недоступности обработчика или истечении срока остаётся браузерный результат с пометкой, что слова не проверены. Серверный ответ заменяет балл и оси; график, найденные моменты и задержка остаются от локального анализа.

При проверке слов ось «Ритм и слова» состоит поровну из базового ритма и оценки слов. Начало слова получает полный балл при отклонении до 0,20 с, затем оценка линейно падает до нуля к 0,60 с. Слово считается найденным при `sung ≥ 0.5`. Если найдено меньше 30% слов, итог ограничен 40 баллами; при сходстве с подсказкой `bleed ≥ 0.45` — 30. При нескольких ограничениях действует самое строгое.

В истории серверная оценка отмечена `algorithm: "precise-1"` и признаком `wordsChecked`. У базовой оценки алгоритм не указан. Сравнивать эти результаты как одинаковые измерения качества следует осторожно.

### Режимы звука

В наушниках играет минус и тихий вокал-подсказка (громкость 0,18), эхоподавление выключено. Без наушников играет только минус, эхоподавление включено. Если дорожки не загрузились, используется исходный `backing.mp3`, а подсказки интерфейса меняются соответственно. Все 32 песни каталога имеют разделённые дорожки.

## Дуэли

Живая дуэль проходит состояния `created → waiting → ready_check → countdown → singing → collecting → finished`. До старта оба клиента подтверждают готовность звука, микрофона, эталона и версии алгоритма.

Клиенты отправляют кривую высоты с шагом 50 мс и точностью 0,1 полутона. Итог считает сервер общим Rust-ядром. **GPU-оценка и распознавание слов в дуэлях не используются.** Сервер не принимает готовый балл от клиента, но подделку самой кривой это полностью не исключает.

Команды WebSocket имеют идентификатор и подтверждение. События нумеруются; после обрыва клиент получает состояние матча. Valkey хранит временное состояние и аренду владельца матча, PostgreSQL — итог и изменение рейтинга. Есть также асинхронный вызов по ссылке. Детали — в [протоколе](docs/protocol.md).

## Каталог и свои треки

Активный каталог — `web/static/songs/index.json`. В папке песни лежат:

| Файл | Содержимое |
| --- | --- |
| `backing.mp3` | Исходный фрагмент с вокалом для прослушивания и запасного воспроизведения |
| `instrumental.mp3`, `guide.mp3` | Синхронные минус и вокал, полученные Demucs |
| `reference.json` | Эталон высоты, длительность, фразы и строки текста |
| `lyrics.words.json` | Времена отдельных слов |
| `CREDITS.json` | Автор, запись, источник, лицензия, изменения и хеши |

Версия эталона — первые 12 символов SHA-256 `reference.json`. Поле `language` задаёт язык распознавания. Для «Ямщик, не гони лошадей», «Ой, то не вечер» и «Дорогой длинною» установлено `wordsCheck: false`: Whisper не находил слова даже в исходном вокале. На этих песнях нет проверки слов и ограничения за их отсутствие; остальные проверки сохраняются.

Свои треки доступны после входа: до пяти загрузок за 24 часа, исходный файл до 30 МБ и до 10 минут. Пользователь выбирает 15–60 секунд. Браузер отправляет только этот отрывок с двухсекундными полями как моно WAV 44,1 кГц; API принимает до 12 МБ и 14–70 секунд. Обработчик создаёт минус, вокал, эталон и слова. Трек доступен только владельцу и удаляется через 24 часа. Ссылка на вызов с таким треком пока не даёт другому пользователю доступ к его файлам.

## Обработчик и очередь заданий

Обработчик сам обращается к API по HTTPS с Bearer-токеном; входящие порты на его компьютере не нужны. На сервере хранится SHA-256 токена. Windows-установщик хранит токен через DPAPI и ограничивает доступ к `C:\Perepev` администраторами и SYSTEM. Процесс запускает Планировщик заданий.

| Модуль | Задача |
| --- | --- |
| `separate.py` | Demucs `htdemucs`: отделение вокала от сопровождения |
| `pitch.py` | torchcrepe `full`: высота с шагом 10 мс, диапазон 65–1100 Гц |
| `words.py` | Whisper `large-v3-turbo` на CUDA / `small` на CPU; сопоставление с текстом через rapidfuzz |
| `bleed.py` | GCC-PHAT: сходство записи с проигранными дорожками |
| `score.py`, `track.py` | Обработка попытки и подготовка своего трека |
| `catalog.py` | Подготовка дорожек каталога и импорт песни |
| `profanity.py` | Маскирование нецензурных корней в распознанном тексте своих треков |
| `main.py`, `client.py` | Получение заданий, сигнал доступности, повтор сетевых запросов |

GPU-задания хранятся в PostgreSQL, а не в Valkey. Получение использует `FOR UPDATE SKIP LOCKED`; аренда действует 120 секунд и продлевается сигналами обработчика. Отдельные потоки получают задания оценки и подготовки трека: по одному заданию каждого вида одновременно. Длительность запроса ожидания — 25 секунд, интервал сигнала доступности — 10 секунд.

Задания оценки после своего срока больше не выдаются. Незавершённая подготовка трека прекращается через 30 минут. Ошибки сети повторяются с задержкой; отклонённый токен останавливает обработчик. При запуске удаляются оставшиеся временные папки `job-*`.

Модели кешируются в `PEREPEV_MODELS_DIR`. Первый запуск требует скачивания; с полным кешем Demucs работает без обращения к Hugging Face. Apple MPS отключён из-за наблюдавшегося чрезмерного расхода памяти. CPU-режим подходит для разработки, но измеренные около 25 секунд на попытку превышают стандартный серверный срок 20 секунд.

## Данные и доступ

| Данные | Хранение |
| --- | --- |
| Аккаунты, сессии, согласия, внешние идентификаторы | PostgreSQL |
| История, друзья, матчи, рейтинг | PostgreSQL |
| Голос для точной оценки | Закрытый том `data`; удаление после обработки, резервная очистка после 7 минут с верхней границей 10 минут |
| Записи попыток и GPU-заданий | PostgreSQL, 24 часа |
| Свои треки и их файлы | PostgreSQL и `data`, 24 часа |
| Обращения через форму | PostgreSQL, один год |
| Подбор, присутствие, события, лимиты, OAuth state | Valkey, с отдельными сроками жизни |
| Гостевая история и настройки | Браузер |

Очистка выполняется раз в минуту. Шесть SQL-миграций встроены в API: базовая схема, согласия, друзья, внешние аккаунты и обращения, GPU-задания, признаки точной оценки в истории.

Яндекс ID и VK ID используют код авторизации и PKCE S256. Одноразовый `state` связан с HttpOnly-cookie и хранится 10 минут. Новый пользователь подтверждает согласие и возрастную группу; для группы до 14 лет форма запрашивает имя родителя. Эти поля не являются проверкой личности или возраста. OAuth-аккаунт создаётся без почты и пароля. Провайдер показывается только при заданных ID и секрете; обмен VK использует публичный PKCE-режим без передачи секрета.

Изменяющие запросы браузера проверяют Origin и специальный заголовок. Маршруты обработчика используют собственную проверку токена. Лимиты запросов общие для экземпляров API: в Valkey хранятся счётчики по адресу либо пользователю. Настройка реальных OAuth-приложений описана [отдельно](docs/oauth-setup.md); тест с подменённым провайдером не подтверждает работу входа через настоящий сервис.

## Прокси, кеш и сборка

nginx заменяет `X-Forwarded-For` адресом соединения. Caddy доверяет частным адресам в режиме за nginx и передаёт API ровно один адрес клиента. В прямом публичном режиме список доверенных прокси пуст. Локальный процесс на том же сервере остаётся внутри доверенной границы; частные адреса клиентов требуют отдельного учёта при изменении сетевой схемы.

HTML, `version.json` и музыка отдаются с перепроверкой кеша (`no-cache`), файлы `/_app/immutable/` — на год, графика и шрифты — на семь дней. Отсутствующий статический файл возвращает 404, а не HTML приложения. Шаблон nginx отключает журнал обычных запросов для этого сайта; ошибки nginx могут содержать IP. Фактически установленную конфигурацию и срок хранения ошибок нужно проверять на сервере отдельно.

Docker собирает Rust API и WASM, затем статический сайт. В сборке запускаются тесты ядра и Vitest. Финальные образы содержат бинарник API и Caddy со статикой; Node.js на сервере приложения не работает. PostgreSQL, Valkey и закрытые данные используют именованные тома. GPU-обработчик устанавливается отдельно.
