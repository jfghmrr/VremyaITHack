# Почему выбраны эти технологии

Перепеву нужны живой отклик на голос, одинаковая логика оценки на клиенте и сервере, дуэли и обработка аудио нейросетями. Стек разделён по этим задачам. Это объяснение подходит и для технических вопросов на защите.

## SvelteKit и TypeScript

SvelteKit даёт маршруты и сборку интерфейса, а статический адаптер позволяет раздавать готовые файлы через Caddy. Для этих страниц не нужен отдельный Node-сервер во время работы. TypeScript помогает согласовать состояния экрана и форматы запросов с JSON-схемами API.

React тоже подошёл бы. Причина выбора не в том, что он «медленный»: для текущего интерфейса удобна модель компонентов Svelte, а статическая сборка упрощает развёртывание. Цена решения — отдельный клиентский стек и необходимость следить за состояниями загрузки в браузере.

## Rust и WebAssembly

Ключевой довод — повторное использование `scoring-core`. Одни функции собираются в WASM для быстрой предварительной оценки и в обычный бинарник для серверного пересчёта. Не приходится вручную поддерживать две реализации формул на разных языках. Тесты сравнивают результаты на одних и тех же данных.

Rust также помогает контролировать память и типы в серверном коде. Он не делает алгоритм автоматически правильным: нужны тесты, корректный эталон и проверка входных данных. Минус — более сложная сборка WASM и менее быстрые изменения, чем в небольшом скриптовом прототипе.

## Axum и Tokio

API одновременно обслуживает HTTP, WebSocket и ожидание заданий обработчиком. Axum и Tokio позволяют держать эти соединения в одном Rust-приложении рядом с ядром оценки. Выбран модульный монолит: его проще запустить и отладить небольшой команде. Микросервисы пока добавили бы больше сетевых границ, чем пользы.

## Web Audio и фоновые потоки

AudioWorklet получает звук отдельно от отрисовки страницы, Worker выполняет анализ, а основной поток показывает график и реагирует на нажатия. Живая линия высоты не ждёт сети. Отдельный сервер для каждого аудиокадра добавил бы задержку и зависимость от связи.

Браузерная оценка остаётся запасным вариантом, когда GPU-ПК выключен. При этом браузеры и устройства по-разному обрабатывают звук, поэтому испытания реальных микрофонов обязательны.

## PostgreSQL и Valkey

PostgreSQL хранит данные, которые нельзя потерять при перезапуске: аккаунты, историю, результаты, рейтинг и задания обработки. Транзакции нужны, например, чтобы два обработчика не забрали одно задание. Очередь GPU-задач использует `FOR UPDATE SKIP LOCKED` в PostgreSQL.

Valkey хранит короткоживущее состояние: подбор соперника, присутствие, события дуэли, OAuth state и счётчики лимитов. Ключи с TTL удобно удаляются по сроку. Это второй сервис, который приходится обслуживать, но временная активность не смешивается с основной историей пользователя.

## WebSocket

В дуэли серверу нужно самому отправлять готовность, отсчёт, состояние соперника и результат. Постоянное соединение удобнее частых HTTP-опросов. За это приходится платить логикой переподключения, подтверждений команд и восстановления состояния — она реализована в протоколе.

## Python и отдельный GPU-обработчик

Для Demucs, torchcrepe и Whisper уже есть Python/PyTorch-инструменты. Переписывать их на Rust ради одного языка было бы лишней работой. Обработчик извлекает признаки, а итоговые формулы остаются в Rust.

GPU-ПК сам забирает задания по HTTPS. Не нужны входящий порт и публичный адрес компьютера; веб-сайт продолжает работать при его отключении. Обратная сторона — очередь, срок ожидания и зависимость точного режима от доступности этого ПК. Несколько обработчиков можно подключить к общей очереди, но пропускную способность ещё нужно измерить.

## Готовые модели

- torchcrepe извлекает высоту голоса из записи. Для живой линии в браузере используется более лёгкий метод McLeod на основе автокорреляции pitchy.
- Whisper распознаёт слова на русском и английском. Его вывод сопоставляется с текстом песни; он не выставляет балл за качество пения.
- Demucs разделяет голос и сопровождение для своих треков и обработки записи с динамика.
- GCC-PHAT ищет совпадение с проигранной подсказкой. Это обработка сигнала, а не нейросеть.

Свою модель качества вокала не обучали: нет достаточного набора записей с согласованными экспертными оценками. Сначала нужно собрать такой набор и понять, где ошибается текущая система. Открытая модель всё равно может ошибаться на распевах, шуме и старой записи; поэтому слово «точная» в интерфейсе не означает гарантированно верную оценку.

Модели скачиваются при установке и затем запускаются локально через PyTorch. Команда не вызывает платные облачные API распознавания. Между сайтом и нашим обработчиком есть собственный HTTP API: по нему передаются задания, записи и результаты. Отсутствие платы за запрос не означает нулевые затраты — нужны видеокарта, электричество и обслуживание.

## Docker и два веб-сервера

Docker фиксирует окружение сборки и запуска API, сайта и баз. Это облегчает перенос между компьютерами, но требует места, памяти и резервного копирования томов.

В локальной установке Caddy отдаёт статику и проксирует API. На сервере команды nginx уже обслуживал другие сайты и HTTPS, поэтому его оставили перед Caddy. Для нового отдельного сервера достаточно варианта с одним Caddy на портах 80/443; два прокси не являются обязательной частью идеи проекта.

## Яндекс ID и VK ID

Эти провайдеры привычны русскоязычной аудитории и позволяют войти без нового пароля. OAuth с PKCE даёт привязку внешнего аккаунта, а собственный вход по почте остаётся запасным вариантом. Выбор провайдера не следует представлять как доказательство полного соответствия сервиса закону.
