# Протокол HTTP и WebSocket, версия 1

Типы сообщений описаны в `crates/api/src/protocol.rs`. JSON-схемы лежат в `contracts/` (`perepev-api schemas contracts`), типы клиента генерируются из них в `web/src/lib/api/types.ts` (`node web/scripts/gen-types.mjs`). После изменения протокола нужно повторить генерацию схем и типов и проверить получившиеся изменения в Git.

## HTTP

Изменяющие JSON-запросы браузера требуют заголовки `Origin` (из `APP_ORIGINS`), `X-Perepev-Request: 1` и `Content-Type: application/json`. Обычное JSON-тело ограничено 16 КиБ; для правки текста своего трека выделен предел 64 КиБ и до 600 слов. Загрузка аудио имеет отдельные типы и лимиты; маршруты обработчика используют Bearer-токен вместо браузерной CSRF-проверки. Ошибки имеют вид `{"error": "понятное сообщение"}`.

| Метод и путь | Что делает |
| --- | --- |
| `GET /api/health` | состояние PostgreSQL и Valkey, экземпляр, соединения, матчи |
| `GET /api/me` | `{profile, rating}` или `{profile: null}`; `profile` = `{id, email\|null, name, hasPassword, providers}` |
| `POST /api/register` | `{email, name, password, consent: true, ageGroup: "14plus"\|"under14", parentName}` → 201, cookie сессии; `parentName` (2–64 символа) обязателен для `under14` |
| `POST /api/login` | `{email, password}` → cookie сессии |
| `POST /api/logout` | удаляет сессию и закрывает её WebSocket на всех экземплярах |
| `PATCH /api/me` | `{name}` |
| `POST /api/password` | `{currentPassword, newPassword}`; отзывает все сессии и соединения пользователя. OAuth-аккаунт без почты не может добавить пароль: API возвращает 400 |
| `POST /api/me/delete` | `{password}`, либо `{confirm: "УДАЛИТЬ"}` для аккаунта без пароля; удаляет аккаунт и связанные данные |
| `GET /api/auth/providers` | `{providers: ["yandex", "vk"]}`: только настроенные провайдеры |
| `GET /api/auth/{yandex,vk}/start?return=/path` | `302` к провайдеру с PKCE S256 и state из 64 символов; временная cookie `perepev_oauth` (`SameSite=Lax`, 10 минут) |
| `GET /api/auth/{yandex,vk}/callback` | `302 {return}` с сессией для известного аккаунта, `302 /account?signup={token}` для нового, `302 /account?authError=state\|denied\|provider\|limit\|server` при ошибке |
| `POST /api/auth/complete` | `{token, consent: true, ageGroup, parentName}` → 201 `{profile}` и сессия; имя `Певец-NNNN` |
| `POST /api/complaints` | `{name, email, url, text}`, каждое поле до 2000 символов, корректная почта → 201 `{id}`; до 5 обращений с IP за час |
| `GET /api/attempts`, `POST /api/attempts` | приватная история одиночных попыток (до 100), повтор `id` идемпотентен |
| `GET /api/rating` | MMR для показа, калибровка, ранг, защита |
| `GET /api/catalog` | песни с версией эталона |
| `GET /api/matches`, `GET /api/matches/{id}` | история дуэлей; итог матча только для участника |

С одного адреса за 15 минут — не больше 12 регистраций и не больше 12 неудачных проверок пароля (вход, смена пароля, удаление кабинета). Успешный вход лимит не расходует. Счётчики общие для всех экземпляров. `POST /api/auth/complete` учитывается как регистрация. Начало входа через провайдера ограничено 60 запросами с IP за 15 минут.

## WebSocket `/api/ws`

Подключение принимается только с разрешённым `Origin` и действующей cookie сессии. Сессия перепроверяется каждые 30 с, отзыв закрывает соединение сразу. Сообщения — JSON-текст до 16 КиБ, не больше 40 команд в секунду (всплеск 80).

### Клиент → сервер

Конверт: `{"v": 1, "id": <номер команды>, "type": ..., ...}`. Сервер отвечает `ack` с тем же `id`. После переподключения клиент повторяет неподтверждённые команды. Все команды идемпотентны.

| type | Поля | Смысл |
| --- | --- | --- |
| `hello` | `match_id?`, `last_seq?` | первое сообщение после подключения; сервер присылает состояние |
| `ping` | `c` (время клиента, мс) | heartbeat каждые 5 с и оценка смещения часов |
| `queue_join` / `queue_leave` | — | рейтинговая очередь; повторный вход не создаёт вторую заявку |
| `room_create` | `song_id`, `mode?` | комната для игры с другом: `versus` по умолчанию, `coop` — пение по очереди |
| `room_join` | `code` | вход по коду комнаты |
| `accept` / `decline` | `match_id` | подтверждение участия в найденном матче |
| `ready` | `match_id`, `song_version`, `algorithm_version` | материалы загружены, микрофон и звук готовы |
| `perf` | `match_id`, `from`, `points[]` | точки канонической кривой: десятые доли полутона (0…1270) или `null` — пауза, до 100 точек |
| `finish` | `match_id`, `count` | кривая отправлена полностью |
| `leave` | `match_id` | выход: до старта — отмена, после — техническое поражение |
| `rematch` | `match_id` | повтор песни в течение 15 минут после завершённого матча; новый матч дружеский, режим сохраняется |
| `voice_share` | `match_id`, `on` | согласие на передачу голоса в `coop`: включение до старта, отзыв в любой момент |

### Сервер → клиент

Конверт: `{"v": 1, "seq"?: n, "type": ...}`.

| type | Смысл | Доставка |
| --- | --- | --- |
| `welcome` | пользователь, время сервера, период heartbeat | при `hello` |
| `pong` | `c` и время сервера `s` | на каждый `ping` |
| `ack` | `id`, `ok`, `error?` | на каждую команду |
| `queue` | `{state: {status, pool, window, since_ms, match_id}}` | при изменении и с каждым heartbeat во время поиска |
| `match` | `{view}` — состояние матча целиком | **важное**: с `seq`, повторяется после переподключения |
| `opponent` | `from`, `points[]` — кривая соперника для анимации | промежуточное: может прийти позже или повторно |
| `room` | `match_id`, `code`, `mode`, `rematch_of?`, `invite` | создана комната или предложен реванш; `invite: true` — приглашение для второго игрока |
| `error` | `message` | адресная ошибка |

### Совместное исполнение

`MatchView.mode` равен `versus` или `coop`. В `coop` сервер передаёт `turns`: список партий с `slot`, `start_s`, `end_s` и индексами `lines`. Песня должна содержать хотя бы две партии. Точки `perf` вне своей партии не участвуют в оценке.

В результате `team` содержит общий `score` и `parts` — разбор каждого игрока: `user_id`, `slot`, `turns`, `seconds`, `score`, `hardest`. При отсутствии результата балл может быть `null`. Совместный матч не меняет рейтинг; исход для обоих — `draw`.

Для настоящих голосов оба игрока включают `voice_share`. Состояние согласия приходит в данных участников. Отзыв прекращает доступ и удаляет записи на сервере. Полученная ранее браузером копия не отзывается.

| Маршрут | Назначение |
| --- | --- |
| `PUT /api/matches/{id}/voice` | Загрузка своей записи после окончания: PCM16, моно, 16 кГц; не длиннее песни плюс 1 секунда |
| `GET /api/matches/{id}/voice/{slot}` | Запись участника; доступ только игрокам матча при двух действующих согласиях |

Обработчики маршрутов находятся в `crates/api/src/voices.rs`. При чтении `404` означает, что запись ещё не поступила; `410` — срок ожидания или хранения закончился; `403` — нет доступа или взаимного согласия. Загрузка разрешена в течение 90 секунд после завершения матча, для завершения запроса предусмотрено ещё 5 секунд ожидания. Файлы очищаются после шести минут хранения с шагом 30 секунд.

### Последовательность, подтверждения, восстановление

- При `hello` сервер восстанавливает активный матч и состояние очереди. Успешное создание комнаты или вход в неё прекращает рейтинговый поиск; неудачная попытка сохраняет его.
- Повторный запрос реванша присоединяется к уже созданной комнате той же пары. Уведомление отправляется при её создании, а не при каждом повторе команды.
- Владелец матча нумерует важные события `seq`. Клиент отбрасывает `seq`, который уже видел.
- Команды доставляются владельцу через поток Valkey `m:{id}:in`, события — через `m:{id}:out`. Поэтому игрок может быть подключён к любому экземпляру и переподключиться к другому.
- После переподключения шлюз отправляет снимок состояния матча, затем события потока с начала (до 4000 записей): все важные и все точки соперника. Итог матча после закрытия вкладки доступен и через `GET /api/matches/{id}`.
- Промежуточные `opponent` можно потерять или получить заново: клиент записывает точки по индексу. Итог `finished` не теряется — он хранится в PostgreSQL и повторяется при каждом подключении.
- Клиент переподключается с экспоненциальной задержкой 0,5–10 с со случайным разбросом ±50%. Неподтверждённые команды ждут в ограниченной очереди (600) и повторяются после подключения.
- Медленный клиент, чья исходящая очередь (512 сообщений) переполнилась, отключается. После переподключения он получает актуальное состояние.

## Хранение временных данных

| Ключ Valkey | Что | Срок |
| --- | --- | --- |
| `kv:q:t:{user}`, `kv:q:pool:{cal,main}`, `kv:q:reserved` | заявки, пулы, резервы пар | заявка 30 с с последнего heartbeat |
| `kv:p:{user}` | присутствие | 15 с |
| `kv:m:{id}:owner`, `:gen` | аренда владельца и поколение | 6 с / сутки |
| `kv:m:{id}:in`, `:out`, `:state`, `:curve:{slot}` | команды, события, снимок, кривые | 2 часа |
| `kv:u:{user}:out` | события пользователя (матч найден, реванш) | 1 час |
| `kv:sys:revoke` | отзыв сессий | 1 час |


## Точная оценка и свои треки

| Маршрут | Назначение |
| --- | --- |
| `POST /api/perf` | Создание попытки с согласием, песней и режимом звука |
| `PUT /api/perf/{id}/chunk?seq=n` | Моно PCM16 16 кГц; до 400 КБ на кусок |
| `POST /api/perf/{id}/finish`, `GET /api/perf/{id}` | Завершение загрузки и получение результата |
| `GET /api/tracks`, `POST /api/tracks` | Список и создание своих треков после входа |
| `PUT /api/tracks/{id}/audio` | WAV до 12 МБ |
| `PUT /api/tracks/{id}/lyrics` | Исправление слов и таймингов готового трека владельцем; обновляет версию эталона |
| `GET /api/tracks/{id}/files/{name}`, `DELETE /api/tracks/{id}` | Файлы владельца и удаление трека |
| `POST /api/worker/lease`, `POST /api/worker/heartbeat` | Получение аренды и сигнал доступности обработчика |
| `/api/worker/jobs/{id}/input`, `/asset/{name}` | Получение входных файлов |
| `/api/worker/jobs/{id}/progress`, `/files/{name}`, `/complete`, `/fail` | Ход обработки, загрузка файлов и завершение |

Точные структуры определены в `crates/api/src/worker.rs`, `perf.rs`, `tracks.rs`, `jobs.rs` и `gpu-worker/perepev_worker/client.py`. Сроки, размеры и правила оценки — в [ARCHITECTURE.md](../ARCHITECTURE.md).
