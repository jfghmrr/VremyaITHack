# Проверка переносимого комплекта

Дата: 16 октября 2026 года. Приложение соответствует функциональной версии `041344f`; комплект дополнен документацией и ожиданием завершения SPA-перехода в одном браузерном тесте. Исполняемый код приложения при упаковке не изменялся.

## Условия

- Чистая копия файлов проекта без Git-истории, node_modules, Rust target, готовой WASM-сборки, Python-окружений и кешей музыки.
- Docker Engine 29.4.3, Compose 5.1.3; Linux ARM64 внутри Docker Desktop на macOS.
- Отдельный Compose-проект `perepev-archive-check`, порт 8086, новые тома PostgreSQL и Valkey.
- Основная установка на localhost:8080 и её пользовательские данные не использовались для тестов.

## Полная Docker-сборка

Выполнена стандартная multi-stage сборка обоих сервисов по `Dockerfile` через `docker compose build`. Собраны API, WASM и статический сайт; готовые runtime-образы основного проекта не использовались как замена исходной сборке. Docker мог использовать свой обычный кеш базовых стадий.

В процессе успешно прошли 8 тестов Rust scoring-core и 66 тестов Vitest. Сервисы поднялись с новой базой, API применил миграции и стал healthy. `/api/health` вернул `ok`, `db` и `valkey` со значением true.

`docker compose config -q` успешно проверил локальную конфигурацию и объединённую серверную конфигурацию с тестовыми значениями домена/пароля. HTTPS-публикация и получение сертификата не выполнялись.

## Браузер и материалы

На новой сборке проверены 8 различных сценариев: регистрация и приватная история, вызов-призрак во втором браузере, живая дуэль, одиночный путь, выбор последней песни гостя, выбор песни из истории аккаунта, повтор аудио после ошибки и правки экранов.

В первом прогоне прошли 7 из 8. Проверка остановки магнитофона читала состояние сразу после клика, до завершения асинхронного перехода. В тест добавлены ожидание адреса `/songs` и опрос состояния паузы; затем этот сценарий прошёл 5 раз подряд. Таким образом, все 8 различных сценариев имеют успешный результат; повторные прогоны не прибавляются к их числу.

Проверки выполнялись в изолированном Chromium. Сценарий интерфейса проверяет 1366×768 и 390×844. Это браузерная проверка с синтетическим микрофоном, а не испытание физического телефона или реального певца.

По HTTP проверены все 24 активные песни: 10 RU / 14 EN. SHA-256 аудио, текстов и эталонов совпали с CREDITS.json; версии эталонов совпали с API. Песни и графика включены в комплект, при запуске не скачиваются с сайтов авторов.

## Состав

Исходники, Docker-конфигурация, миграции, lock-файлы, музыка, изображения, шрифты, лицензии, документация, тесты, тестовые fixtures, скриншоты и презентация. Личные базы, резервные копии, секретные настройки, зависимости и рабочие кеши не включены. Вымышленная SQLite-база в fixtures оставлена для тестов миграции и не загружается при запуске.

`PACKAGE_INFO.json` фиксирует исходный коммит комплекта. `MANIFEST.sha256` перечисляет суммы каждого включённого файла, кроме самого манифеста. Рядом с ZIP поставляется сумма всего архива.

## Распаковка и повторный запуск

ZIP распакован в отдельную папку. Проверены CRC архива, SHA-256 всех 512 перечисленных в манифесте файлов, наличие обязательных Docker/lock-файлов и относительные ссылки новой документации. Всего в архиве 513 файлов, включая сам манифест.

Из распакованной копии повторно выполнена стандартная Docker-сборка с доступным кешем; затем экземпляр запущен после `docker compose down` без удаления томов. API снова стал healthy. Число тестовых записей до и после совпало: 4 пользователя, 1 попытка, 2 матча; применены 3 миграции. Эти тестовые данные не входят в ZIP.

После проверки тестовая среда удаляется отдельно от основной установки. Финальная упаковка меняет только отчёт и сведения о коммите; проверенные исполняемые исходники остаются теми же.

## Границы проверки

Для первой сборки нужен интернет. Установка без доступа к реестрам требует отдельно подготовленных Docker-образов; они в ZIP не входят. Проверка на отдельном Windows/Linux x86-64 компьютере, публичном HTTPS-сервере, Safari/Firefox и реальном микрофоне не проводилась.
