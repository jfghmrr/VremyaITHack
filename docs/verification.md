## Сквозные сценарии в браузере (Playwright, Chrome, синтетический микрофон)

`npx playwright test` — **13 из 13 проходили** до добавления каталога и правовых сценариев; сейчас набор из 17 сценариев проходит целиком (локально и против Docker):

1. Одиночный путь: каталог → проверка микрофона (устройства появляются после разрешения) → Пробел → сцена без навигации → разбор: балл больше 80, «−5 полутонов, без штрафа», намеренная ошибка 5–6 с попала в замечания → A/B «Ориентир» → копирование вызова (ссылка `#echo=` в буфере) → тренировка → возврат к последнему разбору из каталога.
2. Вызов-призрак: ссылка открыта во втором браузерном контексте → баннер вызова → пение против призрака → дуэль с призраком «рейтинг не меняется»; повреждённая ссылка даёт понятную ошибку.
3. Кабинет: регистрация через форму (короткий пароль не отправляется), калибровка 0 из 10, попытка сохраняется в истории, второй аккаунт видит пустую историю, выход (`/api/attempts` → 401), неверный пароль, вход по почте в другом регистре.
4. Живая дуэль с другом в двух независимых контекстах: комната → готовность обоих → общий старт → пение → «Победа» и «Поражение», колонки баллов у обоих зеркально совпадают, балл победителя больше 90.
5. Рейтинговая очередь: пул калибровки, окно ±80, отмена и повторный вход, подбор, подтверждение, готовность, итог; MMR обоих 1000 ± 20 (K = 40), сумма 2000, рейтинговых матчей по 1.
6. Отказы: микрофон запрещён; сохранённое устройство отключено; тишина (балл ≤ 30, «Голоса почти не слышно»); несуществующий трек; пустой разбор; сервер недоступен (одиночное пение работает, кабинет объясняет); нет соперника — через 30 с честное предложение без ботов и счётчика онлайна.
7. Клавиатура: порядок Tab (знак, Петь, Дуэли, Кабинет, Войти, выбор песни), видимый фокус, Enter и Пробел на проверке, пауза Пробелом, Esc открывает диалог, Esc отменяет, Enter подтверждает выход. Найдена и исправлена ошибка: Enter в диалоге отменял выход, потому что фокус стоял на «Продолжить».
8. Размеры: 1366×768 и 1920×1080 без вертикальной прокрутки на главной, проверке микрофона, разборе, дуэлях, кабинете и итоге дуэли; 800 px и масштаб 200% (683 CSS-пикселя) — без горизонтальной прокрутки.

Скриншоты лежат в `docs/screens/`: главная, проверка микрофона, сцена, разбор, кабинет гостя и пользователя, поиск соперника, найденный соперник, готовность, сцена дуэли, итог дуэли, входящий вызов, 200%.

## Нагрузка: 100 одновременных дуэлей

`node tools/load/duels.mjs 100`: 200 WebSocket-клиентов, два экземпляра API, комнаты с другом, реальное время, пакеты примерно каждые 100 мс. Регистрация через отдельный экземпляр, чтобы scrypt не искажал память.

| Показатель | Значение |
| --- | --- |
| Завершены | 100 из 100, результаты пар одинаковые, технических исходов 0 |
| Подтверждение команды (40 000 команд) | p50 4.9 мс, p95 8.5 мс, p99 18.8 мс |
| Кривая соперника на экране (39 400 пакетов) | p50 12.7 мс, p95 18.9 мс, p99 23.9 мс |
| Итог после конца песни | p50 0.69 с, p95 0.89 с, p99 0.91 с |
| Память экземпляра | 5.9 МБ без нагрузки, ~29 МБ со 100 соединениями, пик 48 МБ |
| Процессорное время за прогон | 9.9 с и 3.4 с на двух экземплярах |

Первые прогоны этой проверки выявили настоящую ошибку. Аренда владельца продлевалась после записи поколения в PostgreSQL. Под конкуренцией за пул ожидание доходило до 9–10 с, аренда истекала, и владельцы сдавались. Исправлено отдельной задачей продления, увеличен пул (`DB_POOL=32`), из PostgreSQL убраны промежуточные коммиты состояний. Дополнительно мешал зависший Docker Desktop, который занимал около 8 ядер. Итоговые цифры получены после его остановки.

**Это цель проверки, а не обещанная мощность.** Прогон шёл на одной машине с локальным PostgreSQL. На сервере с другими дисками и сетью цифры будут другими.

## Требования 152-ФЗ

- Сквозные сценарии: плашка cookie видна новому посетителю, ведёт к документам, после «Принимаю» не появляется снова; в подвале ссылки на политику, согласие, cookie и лицензии; реквизиты оператора не выдуманы (видна пометка «не заполнено»); регистрация с отдельным флажком согласия; выгрузка данных в JSON с версией и временем согласия; удаление кабинета с неверным паролем отклоняется, с верным — кабинет удалён, войти больше нельзя.
- Интеграция: время и редакция согласия записываются в базу; выгрузка без сессии — 401; после удаления в таблицах users, sessions, attempts, ratings не остаётся записей пользователя, cookie сбрасывается.
- Найдены и исправлены по ходу: раскрытые настройки кабинета уходили под подвал и были недоступны для клика; стили навигации шапки увеличивали подвал; лимит попыток расходовался успешными входами (теперь считаются регистрации и только неудачные проверки пароля).
