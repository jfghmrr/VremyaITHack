# Проверка перед публикацией в GitHub

17 октября 2026 года. За основу взята папка `Perepev 2`, которую команда передала как новую серверную версию. Проверка выполнялась в отдельной копии и Docker-проекте `perepev-github-qa` на порту 8087, с новыми томами. Производственный сервер и основная локальная установка не менялись.

## Выполнено

| Проверка | Результат |
| --- | --- |
| Docker: API, WASM и статический сайт из исходников | Сборка завершилась, сервисы запущены, API и базы healthy |
| Локальный и отдельный серверный Compose | `config -q` без ошибок |
| Rust workspace | 41 тест пройден |
| Clippy | Без предупреждений с `-D warnings` |
| Svelte / TypeScript | 0 ошибок, 0 предупреждений |
| Vitest | 118 тестов пройдены при Docker-сборке |
| Схемы и типы API | Повторная генерация не изменила файлы |
| Интеграционные сценарии | 43 пройдены с настоящими PostgreSQL и Valkey |
| Python-обработчик без загрузки моделей | 116 пройдены, 4 модельных теста исключены |
| Основные браузерные сценарии Chromium | 32 имеют успешный результат после исправления одного теста |
| Страница ошибки в WebKit | 4 сценария пройдены |
| Раскладка и поворот экрана, Chromium и WebKit | 26 сценариев пройдены |

Интеграционные сценарии проверяют аккаунты, миграцию старых данных, несколько экземпляров API, потерю владельца матча, переподключение, очередь заданий и OAuth с подменённым провайдером. Тестовая база `perepev_ci` и отдельная база Valkey не пересекались с браузерным стендом.

Первый запуск Rust-тестов внутри промежуточного образа не нашёл каталог песен: эта стадия Dockerfile его не копирует. После подключения `web/static` все 41 тест прошли; код приложения для этого не менялся.

В браузерном тесте ошибочной ссылки был выбран путь `/songs/missing/deeper`. В готовой Docker-установке `/songs/*` занят статическими файлами и намеренно возвращает обычный 404. Проверка страницы приложения перенесена на `/missing/deeper`, перед переходом добавлено ожидание загрузки клиента. Повторный прогон страницы ошибки прошёл в обоих движках.

## Проверка в браузере

Всего успешный результат получен для 62 различных сценариев с учётом браузерного движка. Первый основной прогон дал 31 успешный сценарий и одну ошибку в адресе теста; исправленная проверка страницы ошибки затем прошла вместе с остальными тремя в Chromium и WebKit. Повторные сценарии в итоговое число не прибавлены.

Основной набор: `account.spec.ts`, `duel.spec.ts`, `solo.spec.ts`, `precise.spec.ts`, `tracks.spec.ts`, `catalog-free.spec.ts`, `error-page.spec.ts`. Проверены регистрация, изоляция истории, вызов-призрак, живая дуэль, все восемь новых песен, отправка записи, отсутствие согласия, отказ обработчика и загрузка своего фрагмента. В сценариях точной оценки и своих треков ответы GPU подменены; реальная обработка моделями здесь не проверяется.

Из `responsive.spec.ts` выполнены группы телефонов и настольных экранов, включая сцену пения, результат и поворот телефона: по 13 сценариев в каждом движке. Размеры: 360×740, 390×844, 430×932, 844×390, 932×430, 1280×720, 1366×768, 1920×1080, 2560×1440, 3440×1440. Планшетная группа в этом повторном прогоне не запускалась. Отдельно просмотрены снимки главной на телефоне и десктопе, а также сцены пения на мобильном размере.

## Команды

Rust и клиент:

```sh
cargo test --release --workspace
cargo clippy --release --workspace --all-targets -- -D warnings
cd web
npm ci
npm run check
npm test
npm run build
```

Интеграционные тесты требуют собранный API, `psql`, `valkey-cli` и отдельные базы. Они очищают указанные тестовые хранилища:

```sh
TEST_DATABASE_URL=postgres://USER@localhost/perepev_test \
TEST_VALKEY_URL=redis://127.0.0.1:6379/1 \
node --test --test-concurrency=1 tests/integration/
```

Браузерные сценарии запускают из `web` после установки браузеров:

```sh
npx playwright install chromium webkit
BASE_URL=http://127.0.0.1:8087 npx playwright test
```

Команда выше запускает полный набор. В этой проверке выполнен выбранный набор, перечисленный выше, а не все сценарии репозитория. Python из `gpu-worker`:

```sh
uv sync --frozen --extra cpu
uv run --frozen --extra cpu pytest -m "not models"
```

## Границы проверки

Docker работал на ARM64 в Docker Desktop на macOS. Физические Android/iPhone, настоящий микрофон, Bluetooth, GPU на Windows и полный вход через реальные OAuth-сервисы в этом прогоне не проверялись. Браузерные проверки используют синтетический микрофон; точные ответы обработчика в соответствующих сценариях подменены.

Сохранённый [GPU-бенчмарк](../gpu-worker/bench/RESULTS.md) относится к отдельному прогону 16 октября: 54 завершённых задания, 48 выполненных исходных ожиданий. Эти числа не прибавляются к новым проверкам и не означают проверку качества на живых певцах.
