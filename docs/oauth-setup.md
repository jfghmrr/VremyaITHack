# Вход через Яндекс ID и VK ID: регистрация приложений

Кнопки «Войти через Яндекс ID» и «Войти через VK ID» появляются на сайте, только когда для провайдера заданы ID и секрет приложения. Без них сайт работает как раньше: вход по почте и паролю.

Ключи и секреты — только в файле `.env` рядом с `compose.yaml` на сервере или своём компьютере. В репозиторий, чат и скриншоты их не добавлять. Если секрет утёк, перевыпусти его в кабинете провайдера и замени в `.env`.

Шаги сверены 16 октября 2026 года с документацией [Яндекс ID](https://yandex.ru/dev/id/doc/ru/) и [VK ID](https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/create-application); полный вход через настоящие сервисы не подтверждён. Интеграционные тесты используют подменённый провайдер; ранее отдельно проверялось начало перенаправления с реальными настройками.

## Адреса сайта

| Где | Адрес возврата Яндекса | Адрес возврата VK |
| --- | --- | --- |
| Сервер | `https://perepev.lumnex.ru/api/auth/yandex/callback` | `https://perepev.lumnex.ru/api/auth/vk/callback` |
| Локально (Docker на порту 8080) | `http://localhost:8080/api/auth/yandex/callback` | `http://localhost:8080/api/auth/vk/callback` |

Сайт строит адрес возврата из `PUBLIC_ORIGIN`, а если он не задан — из первого адреса в `APP_ORIGINS`. На сервере это `https://perepev.lumnex.ru`, локально — `http://localhost:8080`. Адрес у провайдера должен совпадать символ в символ, включая `http`/`https` и порт.

## Яндекс ID

1. Войди в аккаунт Яндекса команды и открой <https://oauth.yandex.ru/client/new/id>.
2. Выбери «Для авторизации пользователей».
3. Укажи название «Перепев» и, по желанию, иконку.
4. Платформа — «Веб-сервисы».
5. В поле Redirect URI добавь оба адреса:
   - `https://perepev.lumnex.ru/api/auth/yandex/callback`
   - `http://localhost:8080/api/auth/yandex/callback`
6. В доступах к данным выбери «Логин, имя и фамилия, пол». Почта, телефон и другие данные не нужны: сайт берёт только постоянный идентификатор пользователя и даёт ему нейтральное игровое имя «Певец-NNNN».
7. Укажи почту для связи и создай приложение.
8. На странице приложения скопируй «ClientID» и «Client secret».

## VK ID

1. Открой кабинет VK ID для бизнеса: <https://id.vk.ru/about/business/go>. Войди аккаунтом команды.
2. Перейди в «Мои приложения» → «Добавить приложение».
3. Укажи название «Перепев», платформу «Web».
4. «Базовый домен»: `perepev.lumnex.ru` и `localhost`.
5. «Доверенный redirect URL»:
   - `https://perepev.lumnex.ru/api/auth/vk/callback`
   - `http://localhost:8080/api/auth/vk/callback`
6. Нажми «Создать приложение» и открой его настройки. Скопируй «ID приложения» и «Защищённый ключ».
7. В разделе «Ключи доступа» не меняй «Уровень конфиденциальности» на «Конфиденциальное»: сайт обменивает код по PKCE без `service_token`, а конфиденциальное приложение VK без него не пускает.

Сайт запрашивает у VK только базовые данные профиля (`vkid.personal_info`) и использует постоянный идентификатор пользователя.

## Настройки сайта

Добавь в `.env` рядом с `compose.yaml`:

```dotenv
YANDEX_CLIENT_ID=значение ClientID
YANDEX_CLIENT_SECRET=значение Client secret
VK_CLIENT_ID=значение «ID приложения»
VK_CLIENT_SECRET=значение «Защищённый ключ»
# Необязательно: адрес сайта для redirect_uri, если он отличается от первого адреса APP_ORIGINS.
# PUBLIC_ORIGIN=https://perepev.lumnex.ru
```

Можно включить только одного провайдера: тогда задай только его две переменные.

Пересоздай сервисы, чтобы они прочитали настройки. Для сервера проекта за nginx используется обычный Compose; вариант с `compose.server.yaml` предназначен только для отдельного сервера, где Caddy занимает порты 80/443:

```sh
# Сервер за nginx и локальная установка
docker compose up -d --wait --wait-timeout 180
```

Проверка: `https://perepev.lumnex.ru/api/auth/providers` (локально `http://localhost:8080/api/auth/providers`) должен вернуть `{"providers":["yandex","vk"]}`. Затем нажми кнопку входа в кабинете: после подтверждения у провайдера новый пользователь увидит согласие и вопрос о возрасте, а при повторном входе сразу попадёт на сайт.

## Если вход не работает

| Сообщение или симптом | Что проверить |
| --- | --- |
| Кнопок нет | Обе переменные провайдера заданы и не пустые; API перезапущен. |
| Провайдер пишет о неверном redirect_uri | Адрес возврата у провайдера совпадает с таблицей выше; `PUBLIC_ORIGIN` или первый адрес `APP_ORIGINS` верный. |
| `/account?authError=state` | Вход занял больше 10 минут, вход начат в другой вкладке или ссылку открыли в другом браузере. Начни вход заново. |
| `/account?authError=denied` | Пользователь отменил вход у провайдера. |
| `/account?authError=provider` | Неверный секрет или ID приложения, провайдер недоступен с сервера, у приложения VK включён уровень «Конфиденциальное». Подробности — `docker compose logs --tail=100 api` (токены и секреты в журнал не пишутся). |
